Methodology

Data flow

  1. Browser polls GET /markets?status=open on the Kalshi demo REST API every 8 seconds (public endpoint — no API key needed; source: Making Your First Request).
  2. Markets are filtered to 5 topics (gas prices, elections, culture, crypto, golf) by keyword match on ticker/title/event ticker, grouped by event, ranked by dollar activity (volume_fp + open_interest_fp).
  3. Each poll compares last_price_dollars to the previous poll; moves ≥ $0.10 post to both alert chats (high-ROI chat additionally requires model score ≥ 60).
  4. Order book from GET /markets/{ticker}/orderbook?depth=10 shows contracts available at each price.
  5. Markets are tracked until status = settled; result (yes/no) is logged and paper positions settle at $1.00/contract.

Why polling instead of WebSocket? Kalshi WebSocket channels require API-key authentication (signed requests — API Keys). The demo WS endpoint is wss://external-api-ws.demo.kalshi.co/trade-api/ws/v2 (Demo Environment); credentialed streaming is a documented roadmap item.

Model score (transparent heuristic, 0–100)

ComponentFormulaMax
Liquidity (volume)min(30, log10(volume+1) × 10)30
Open interestmin(20, log10(open_interest+1) × 8)20
Spread tightnessmax(0, 20 − (ask−bid) × 200)20
Price extremity (near 50¢ = most room to move)max(0, 20 − |last−0.5| × 40)20
Momentum bonusmin(10, |recent move| × 100)10

This is a ranking heuristic for filtering alerts — not a prediction of returns. Paper-trading results are the only evidence, and they are simulated.

Limitations

  • Demo prices “may not be reflective of those in real markets” (Demo Environment).
  • Topic mapping is a keyword heuristic — unverified tickers (see Flagged page).
  • Alert “catalyst” links are curated official sources to check, not proven causes.
  • Simulated fallback data is labeled and never mixed silently with live data.
