What is in the feeds right now. Nothing yet, and that is the honest state. An alert needs the same market observed at two different times, at least $0.10 apart. The committed record has no observation cycles in it, so both feeds are empty rather than showing a stand-in row. The scheduled collector appends real swings here, each with its own observation time, and the banner above switches from "committed alert record" to a live count as soon as it does.

Why no example row: a made-up row would be the one thing this project refuses to publish. See F-11 for how poll-to-poll detection can miss or split a move, and F-01 for why the authoring sandbox could not produce a second observation itself.

The right-hand feed is not a return forecast. It is ranked by a 0–100 score built from the size of the move, the contracts resting where you would have to trade, the spread, 24-hour volume and how fresh the observation is. There is no backtest behind it. The brief called this feed "high ROI"; calling a heuristic ROI would be false, so it is labelled a heuristic everywhere. The scoring rule is published in full on the Methodology page and flagged as F-10.

Why a swing happened

No feed here claims a cause. Kalshi's API returns prices and volumes, never a reason. What each alert row gives you instead: the market and its order book, so you can see the book the move happened in, and the settlement sources Kalshi itself names for that contract, which is where the outcome will be reported. That is a starting point for research, not an attribution. See F-12.
