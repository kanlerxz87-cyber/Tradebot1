Executive summary

A working dashboard over Kalshi's demo exchange, limited to five topics, that watches for $0.10 price swings, follows markets to a finalized yes or no, and runs five simulated strategies. It is built so that a reader can check every number against an official source, and so that anything unverified is published as unverified rather than quietly filled in.

Key findings from the verified data

1. The demo's topic taxonomy does not match the brief

Crypto, Elections and Culture exist as official series categories. Golf and Gas do not. Golf is a tag on Sports series. "Gas" as a tag returns only two diesel series, and a Gasoline tag does not exist at all. The dashboard adapts rather than pretending: it uses the tag where the category is missing, and says so on the topic page and in flags F-03 and F-04.

GET /series?category=Golf · GET /series?tags=Gas

2. Liquidity in these topics is thin, and often one-sided

The golf markets inspected show a YES bid of $0.00 and a YES ask of $1.00 on every row, which is an empty book on both sides rather than a price. The gas series have no open markets at all. Any "highest dollar live events" ranking over the demo is therefore dominated by a handful of markets, and the board says so with a dash wherever a book is empty.

3. Sell-side prices must be derived, not read

Kalshi's order book contains bids only: a YES bid at X is a NO ask at 1−X. Any dashboard that shows an ask without saying it is derived is showing an inference as an observation. This build labels every derived ask and publishes the exchange's own explanation.

Kalshi: order-book responses

4. Fees are a real cost that most simulations skip

At $0.50, Kalshi charges $1.75 per 100 contracts, and the formula is symmetric so it costs the same on the way out. A simulated strategy that ignores the fee can look profitable while losing money. The model here charges the published fee on every entry; the one row of Kalshi's own fee table that its formula cannot reproduce is flagged as F-02 rather than special-cased.

Fee schedule

5. "Why did it move" cannot be answered from this API

No Kalshi endpoint returns a cause. The best available substitute is the settlement source list the exchange names for each series, which is where the outcome will be reported. This build links those and never labels an article as the cause of a move.

Get Series

6. Execution cannot live in the page

Signed requests need a private key and a timestamp within 30 seconds of Kalshi's clock. A static Pages site cannot hold the key. This build keeps all signing in GitHub Actions, and deliberately does not send orders at all, so nothing here can trade by accident.

How to audit this in ten minutes

  1. Open Sources and confirm the endpoint table matches Kalshi's environments page.
  2. Pick any market row and follow its source link to the demo API. Compare the bid and ask with the dashboard.
  3. Open a market page and check the ladder against the raw order book. Confirm the ask column is the complement of the NO bids.
  4. Read Flagged for review and challenge any flag you disagree with.
  5. Run node --test tests/*.test.mjs and confirm the fee model reproduces Kalshi's published table.
