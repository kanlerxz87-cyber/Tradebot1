04Simulated book and resolution tracker

Four strategies trade the same signals every cycle into an internal ledger. The book is simulated: no Kalshi demo account is connected, so no demo balance, positions or fills exist to report. Resolutions are read from the exchange's own result field once a market is finalized.

07Flagged for review — integration level

These are irregularities found while auditing the combined repository, not any single implementation's own list. Each is published here with its evidence so it can be reviewed after the site is live. Nothing below blocks the deployment, and no value anywhere on this site is inferred to fill a gap.

IDSeverityFindingEvidenceHandling
I1warn The site mixes production and demo market data. The desk reads external-api.kalshi.com (production); the monitor reads external-api.demo.kalshi.co (demo). The same series can therefore show different prices on two pages. API environments · collect.yml Disclosed on every page. Demo books are empty (I2), so production data is the only usable feed; the demo host is still wired and switchable by environment variable.
I2warn Demo order books are effectively empty. On the published monitor, sampled contracts quote $0.00 / $1.00 or $0.01 / $0.99, so "contracts resting at a price" is real but near-zero. Any liquidity read from the demo host is not a trading signal. published monitor · orderbook shape Liquidity panels always name their source host. The desk's depth ladder reads production books.
I3info The collector runs against production, not the demo account the brief names. KALSHI_DATA_ENV: prod is set in the collection workflow. This was a deliberate choice (see I2) but it is a deviation from the brief and is recorded rather than hidden. collect.yml Reversible by changing one environment variable; no code change required.
I4warn The monitor's committed seed snapshot was an empty stub. docs/data/snapshot.json was committed as {"generated_at":null,"partial":true,"events":[]}, and the builder swallowed its own errors, so a failed fetch would publish an empty page while reporting success. build_snapshot.py Fixed in this session: per-request isolation, partial results kept, both documented demo hosts tried, and a non-zero exit when nothing was collected.
I5info The published desk snapshot carried ten collection warnings. The settled-market sweep sent min_close_ts as a float and Kalshi rejected it with HTTP 400. Fixed by PR #9; the snapshot shown here predates that fix. PR #9 Warnings are printed on the desk rather than suppressed. The next scheduled cycle clears them.
I6info Alert and resolution counts start at zero. The collector has been running since 2026-11-22. Both chats and the resolution table fill as cycles accumulate; they are not pre-seeded with invented history. collection runs Stated in place. No synthetic alerts were added to make the page look busier.
I7warn Carried forward: fee model unverified, demo account not connected, browser CORS untested. These belong to the desk and are documented there with their own sources. They are repeated here so a reader of this page does not have to find them. desk flagged page Ledger rows are labelled fee_model=quadratic_unverified; the dashboard shows an explicit "not connected" block; the UI reports the CORS test result honestly.
