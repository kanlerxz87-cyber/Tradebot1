Live desk: one process, five topics, two alert chats

A dependency-free Python server (live/) plus a single-page dashboard. It tracks gas prices, elections, culture, crypto and golf; alerts on every move of 10¢ ($0.10) or more in either direction; charts price against time with selectable windows; shows resting contracts at each price; runs four automatic strategies in a simulated book; and keeps each market until Kalshi finalises it. This page is the published record of what it does and what has been verified — the process itself runs on a machine with network access to Kalshi, which GitHub Pages does not provide.

Two data modes, always labelled. --mode live polls the official demo REST API and shows only quotes that came from a response. --mode simulated (the default when there is no egress) replays a seeded random walk anchored to the committed capture so the mechanics can be inspected offline. Every surface names which one is running, and the simulation's alerts are never presented as Kalshi events.

Run it

python3 live/server.py --port 8000                 # auto: try live, fall back to labelled simulation
python3 live/server.py --mode live --interval 1    # poll the demo REST root
python3 -m unittest discover -s live/tests         # 29 tests, no network needed
python3 live/build_page.py --check                 # this page is current

Corrections to earlier notes in this repository

Status vocabulary

An earlier register read the documentation as saying markets are open or settled and flagged the API's active/finalized as a contradiction. The lifecycle page lists active and finalized as the statuses, and open/settled as filter values that map onto them. The API is consistent with its documentation; the earlier reading was not.

result can be scalar

The lifecycle page states result is yes, no or scalar. A resolver that accepts only yes/no will mis-handle a scalar market, so this desk carries the value through unchanged and never coerces it.

What it will not do

  • Place an order. There is no POST handler, no order path and no credential read anywhere in live/.
  • Invent a cause for a price move. Each alert shows the rule text, the contract link and a news search, labelled as a search.
  • Present a simulated price as a Kalshi quote. The mode badge and the banner say which is running, and the JSON carries simulated: true on every simulated alert.
  • Treat a resolved market as open or vice versa: only Kalshi's own status and result fill that table.
