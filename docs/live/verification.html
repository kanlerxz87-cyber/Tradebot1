Fee model reproduced against the published table

feeCents(p, C) = ceil(0.07 × C × p × (1-p)) to the cent, for a taker fill. The published General Trading Fees Table (S12) prints 21 prices; the checker in docs/live/check_live.py asserts all 21 in both columns on every run.

Single-contract rows are the published table's rounding of a sub-cent fee; the console therefore shows both the six-decimal fee and the cent-rounded figure (S13).

What was run, and what it proved

  • node --test docs/live/tests/*.test.mjs — unit tests for quotes, books, swings, fees, routing, resolution and the ledger.
  • python3 docs/live/check_live.py — data contract: every market row carries an http(s) source URL and a read time, every fact has an official URL, the 21-row fee table reproduces, and the console's element ids the shared checker looks for are present.
  • Live reads: GET /exchange/status, /search/tags_by_categories, /series/KXAAAGASM, /series/KXDEMOFUTHOURLY, /events/KXAAAGASM-26NOV30, /markets?tickers=… and /markets/{ticker}/orderbook, all against external-api.demo.kalshi.co on 2026-11-22 between 07:26Z and 07:29Z. Verbatim results are quoted on this page and on the flagged page.
  • The exact request URL that produced every value is committed beside the value in docs/live/data/live.json.

Not run

  • No authenticated call of any kind: there is no demo API key in this repository and none was requested. Balance, positions and order placement are therefore unverified (see the flagged page).
  • No WebSocket subscription was established from a browser: the handshake requires a signed request (S10).
