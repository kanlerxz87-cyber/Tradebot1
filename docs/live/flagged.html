Verbatim observations behind the flags

Each block is a response exactly as the demo host returned it on 2026-11-22, with the request line above it. Nothing is paraphrased.

F1 · An empty book is reported as a 100¢ ask

GET https://external-api.demo.kalshi.co/trade-api/v2/markets/KXAAAGASM-26NOV30-3.00/orderbook?depth=10
200 {"orderbook_fp":{"no_dollars":[],"yes_dollars":[]}}

market object, same market:
"last_price_dollars":"0.9800","yes_bid_dollars":"0.0000","yes_ask_dollars":"1.0000",
"no_bid_dollars":"0.0000","no_ask_dollars":"1.0000","yes_bid_size_fp":"0.00","yes_ask_size_fp":"0.00"

An ask of 1.0000 beside a bid of 0.0000 with zero size on both sides is the empty book, not an offer at par. Taking the midpoint of that pair would print 50¢ for a contract whose last trade was 98¢. The console therefore requires a two-sided, uncrossed book for a mid and otherwise falls back to the last trade, and it prints which basis it used on every row.

F4 · The demo BTC market is not in the Crypto category

GET https://external-api.demo.kalshi.co/trade-api/v2/series/KXDEMOFUTHOURLY
200 {"series":{...,"categories":["Test"],"category":"Test","tags":["Demo"],
    "frequency":"hourly","title":"Demo hourly event contract futures",
    "settlement_sources":[{"name":"Coinbase Exchange",
    "url":"https://api.exchange.coinbase.com/products/BTC-USD/candles"}]}}

The only heavily traded demo market visible in the catalogue is a Bitcoin-price event filed under the Test category with the Demo tag. Routing it to Crypto would be an editorial choice, so it is not routed and this is stated on the Crypto tab. Production Crypto series are a separate question the demo catalogue cannot answer.

F7 · The demo prices disagree with production for the same gas contract

demo:  KXAAAGASM-26NOV30-3.00  last_price_dollars 0.9800  (empty book)
production, earlier session on main (docs/desk/data/sources.json S25):
       GET /markets?series_ticker=KXAAAGASM&status=open returned strikes
       3.45 / 3.55 / 3.65 — the 3.00 strike is not in the open production set

This is expected of the demo environment (S14) but it means no demo price on this page can be read as an estimate of a production price. The console labels every figure as a demo value.

F11 · Unauthenticated WebSocket handshake

recorded by the repository's connectivity probe (GitHub runner, run 44997761812):
wss://external-api-ws.demo.kalshi.co/trade-api/ws/v2   -> HTTP 401
body: {"code":"token_authentication_failure","message":"token authentication failure"}
server-side consumers: one batch of four markets between two page loads
this browser: the console's self-test records the close event it actually receives

A live stream therefore needs a signed handshake, which needs a private key, which a public static page cannot hold. The console polls instead and says so; it does not call itself a stream.

F9 · The demo catalogue may not contain Elections, Culture or Golf markets

GET https://external-api.demo.kalshi.co/trade-api/v2/search/tags_by_categories
200 tags_by_categories includes Crypto, Elections, Entertainment, Sports (Golf), Economics, Commodities ...
    and no "Gas" and no "Culture" entry.

The official category list is complete, but whether the demo catalogue carries open events in each of the five requested topics is a separate, empirical question answered only by the scheduled capture. Empty topic tabs are reported as empty rather than filled with examples from another topic.
