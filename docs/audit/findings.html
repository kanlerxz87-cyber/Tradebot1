AUD-01 Fixed, re-checked on every build high

The swing detector built a midpoint from an empty side, so a 14c bid read as 57c

The trade board's yesMid() was written to reject a bid of 0 or an ask of 1, and its own comment said each was 'an empty side, not a traded price', but the code only returned null when both were true at once. Every one of the eight markets in this repository's own demo capture (data/snapshot.json) has yesAsk 1.0 with an empty NO book, so the sentinel is the normal case. (0.14 + 1.00) / 2 = 0.57 would then flip to a real midpoint the moment an offer appeared: a phantom move far above the $0.10 alert threshold, in the feed a trader reads as news.

Impact. False swing alerts in the unfiltered chat, and a false 'model likes this' candidate in the filtered chat, from quote mechanics rather than from any market event.

Correction. yesMid() now rejects the pair when either side is empty, which is what its comment already described.

AUD-02 Fixed, re-checked on every build high

The research desk's normaliser had the same phantom midpoint, one layer deeper

normalize_market() took yes_ask_dollars at face value and formed the midpoint whenever ask >= bid. With the demo sentinel that is 0.57 for a 14c market, and that value becomes the price feed that the >= $0.10 alert rule, the watchlist and the paper ledger all read. The same defect therefore reached the alerts, the ROI screen and simulated fills, not just one chart.

Impact. The desk's alert feed could fire on a sentinel change, and its paper book could mark a position at a price no one was quoting.

Correction. A reported ask of 1.0000 with no NO bid is now treated as no offer, which is the documented reciprocity: a YES offer can only rest against a NO bid. The midpoint then falls back to the last trade, and the spread is reported as unknown rather than 0.86.

AUD-03 Fixed, re-checked on every build high

The settled sweep sent a filter combination the API rejects, so the tracker recorded nothing

The desk asked GET /markets for status=settled together with min_close_ts. Get Markets documents min_close_ts as compatible with closed (or no status) and pairs settled with min_settled_ts instead. The cycle recorded in this repository before the fix failed this way for each series it swept, with HTTP 400 'Invalid format for parameter min_close_ts', and the resolution list stayed empty; the record of that cycle is quoted on COORDINATION.md. A parallel session has since reworked the same sweep for a different defect (series selection and row caps, PR #16), so the 120 rows now published are theirs as much as this fix's - what is asserted here is only that the parameter is the documented one.

Impact. 'Track events until they resolve' could not work while every settled query was rejected, and an empty resolution table looks like a quiet week rather than an error.

Correction. The sweep now sends min_settled_ts with status=settled. A parallel session reached the same conclusion from the same table and landed the one-line change on main first (PR #16, with a per-topic series sweep and the same integer assertion); this branch therefore keeps main's implementation and its test rather than duplicating the edit. What this audit adds is the official statement behind it and a re-check that runs on every build.

AUD-04 Open — flagged low

Simulated fees are rounded to the whole cent; the exchange rounds a fill to $0.000001 and aligns the balance to $0.0001

Both fee implementations round the formula's result up to the whole cent, which is what reproduces the printed summary table. It is not the per-fill rule: Fee Rounding states that a trade fee is rounded up to $0.000001 and the balance is then aligned to $0.0001 for a direct member, with a rebate accumulator across an order's fills. At 100 contracts and $0.05 the two rules differ by $0.0075 (0.34 versus 0.3325).

Impact. Every simulated P&L figure is at most one cent per fill pessimistic. The difference is disclosed here and next to the performance numbers rather than silently changed, because changing it would also rewrite historical results on the board.

AUD-05 Fixed, re-checked on every build medium

The 'unreproducible fee row' was a column misread, not a gap in Kalshi's table

The board published a flag (F-02) saying one row of Kalshi's own fee table could not be reproduced from Kalshi's own formula, and excluded it from its test fixture. The table has four columns: price for 1, fee for 1, price for 100, fee for 100. The excluded row reads '$0.01 | $0.01 | $1.00 | $0.07'; the $1.00 is the price of 100 contracts, and the fee is $0.07, which 0.07 x 100 x 0.01 x 0.99 = 0.0693 rounds up to exactly like every other row.

Impact. A false flag against the exchange, and a test that quietly verified 20 rows where 21 were available.

Correction. The table entry is $0.07, all 21 rows are asserted in both columns, and flag F-02 is rewritten on the board's Flagged page to record the correction.

AUD-08 Fixed, re-checked on every build medium

The 'committed HTML matches the data' gate failed on every checkout and, differently, inside CI

scripts/build-site.mjs --check compared the committed pages with a fresh render, normalising only the data-generated attribute. Two more pieces of a page are a function of the machine rather than of the data: the relative age ('21m ago', which moves every minute) and the build badge, which prints GITHUB_SHA in Actions and 'local' outside it. The result was a gate that reported all nineteen pages stale on a developer's checkout and, in CI, reported exactly one page stale for a reason no reader could see. CI ran build and check back to back, which hid the first half; the Pages workflow and the audit's own re-check exposed the second.

Impact. A published verification command that always fails gets ignored, and with it the source-link gate it was meant to protect. The failure that only happened in CI was the worse of the two, because that is where the site is actually built.

Correction. The comparison normalises relative ages and the build badge as well as the generated stamp. A no-op rebuild is a no-op in both environments, and a genuine data change still fails the check.

AUD-09 Flag withdrawn info

Flag withdrawn: the status values are not a documentation contradiction

An earlier flag claimed the API contradicts the docs because responses say active and finalized while the docs say open and settled. Market Lifecycle documents both vocabularies and says which is which: responses carry initialized, active, inactive, closed, determined, disputed, amended, finalized, and the ?status= filter accepts unopened, open, paused, closed, settled, each mapping onto a response value. The desk's status=settled sweep is correct usage on that point, and its failure had a different cause (AUD-03).

Impact. None on the code; the earlier flag can be closed with a source rather than left open.

AUD-12 Fixed, re-checked on every build low

or-fallbacks hide a genuine zero quote behind the legacy field

Values are read as first_float(...) or price_from_cents(...). A leg whose real fixed-point value is 0.0 is falsy, so the reader falls through to the legacy cent field, which may be absent (None) or stale. The result is None or an old price where the true value is zero.

Impact. Low: zero prices are the boundary of the book, and downstream guards treat them as an empty side anyway. It is still the wrong way to choose between two representations.

Correction. Replaced the falsy or-fallbacks with an explicit None check (_pick_price), so a quoted 0.0000 dollar price stays 0.0 instead of falling through to legacy cent fields.
