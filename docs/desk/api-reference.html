6 · Orderbook structure

The single most misread part of the API: there are no asks.

Shape

{
  "orderbook_fp": {
    "yes_dollars": [["0.0100","200.00"], ["0.4200","13.00"]],
    "no_dollars":  [["0.0100","100.00"], ["0.5600","17.00"]]
  }
}

Arrays are ascending; the best bid is the last element. Each entry is [price_dollars, count_fp].

Derived ask

A YES bid at $0.42 equals a NO ask at $0.58. Therefore:

best YES ask = 1.00 − best NO bid
best NO ask = 1.00 − best YES bid
spread = best YES ask − best YES bid

Source: Orderbook Responses.

Flag: Kalshi documents that WebSocket connections authenticate with API-key headers. Whether the public channels accept an unauthenticated socket is not stated in the pages read, so this build keeps REST polling as the always-available path and treats WebSocket streaming as credential-gated.
