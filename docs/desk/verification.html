4 · Source register

One row per verified claim. Rows marked unverified would be left blank on the site rather than filled in.

IDClaimPublisherLinkStatus
S1 Demo REST base URL is https://external-api.demo.kalshi.co/trade-api/v2 (recommended) and https://demo-api.kalshi.co/trade-api/v2 is also supported. Production is https://external-api.kalshi.com/trade-api/v2. Kalshi documentation official source verified
S2 Demo WebSocket URL is wss://external-api-ws.demo.kalshi.co/trade-api/ws/v2; wss://demo-api.kalshi.co/trade-api/ws/v2 is also supported. Production is wss://external-api-ws.kalshi.com/trade-api/ws/v2. Kalshi documentation official source verified
S3 Authenticated requests carry KALSHI-ACCESS-KEY, KALSHI-ACCESS-SIGNATURE and KALSHI-ACCESS-TIMESTAMP. The signed text is timestamp + HTTP method + request path, excluding the query string and host. Kalshi documentation — Request Signing section official source verified
S4 RSA keys sign with RSA-PSS and SHA-256; Ed25519 keys sign the message directly. Signatures are base64 in KALSHI-ACCESS-SIGNATURE; the timestamp is Unix milliseconds. Kalshi documentation — securitySchemes official source verified
S5 Public market-data endpoints (series, events, markets, orderbook) require no API key. Kalshi documentation official source verified
S6 Market objects expose yes_bid_dollars, yes_ask_dollars, no_bid_dollars, no_ask_dollars, last_price_dollars, previous_price_dollars, volume_fp, volume_24h_fp, open_interest_fp, yes_bid_size_fp, yes_ask_size_fp, status, result, close_time and rules_primary. Kalshi documentation official source verified
S7 Orderbook responses contain only bids: orderbook_fp.yes_dollars and orderbook_fp.no_dollars as [price_dollars, count_fp] pairs sorted ascending; the best bid is the last element; asks are implied as $1.00 − the opposite side's bid. Kalshi documentation official source verified
S8 Candlesticks: GET /series/{series_ticker}/markets/{ticker}/candlesticks with start_ts and end_ts in seconds and period_interval of 1, 60 or 1440 minutes; at most 5,000 periods per request. Kalshi documentation official source verified
S9 A series has one primary category, a categories discovery list and a tags subcategory list. The category filter matches any entry in categories. Official categories include Elections, Crypto, Entertainment, Sports, Economics and Commodities. Kalshi documentation — Kalshi Glossary official source verified
S10 Golf is a tag (subcategory) inside the Sports category. Full category→tag map retrieved from the live API. Kalshi documentation + live GET /search/tags_by_categories official source verified
S11 The monthly US gas price series is KXAAAGASM: primary category Economics, categories [Economics, Commodities], tags [Oil and energy, Oil & Gas], one event per month with one market per strike. Kalshi documentation — worked example in the glossary official source verified
S12 Settlement: a YES outcome pays $1 per YES contract, a NO outcome pays $1 per NO contract; only net positions settle. Kalshi documentation official source verified
S13 Order placement uses POST /portfolio/events/orders with ticker, side, count, price, time_in_force, self_trade_prevention_type and an optional client_order_id; HTTP 201 means the order was accepted (not necessarily resting). Kalshi documentation official source verified
S14 Rate limits are token buckets per tier; most requests cost 10 tokens; GET /portfolio/balance has its own bucket of 1–5 requests per second; unauthenticated public requests are limited separately and 429s should be retried with backoff. Kalshi documentation official source verified
S15 The ticker WebSocket channel sends price_dollars, yes_bid_dollars, yes_ask_dollars, volume_fp, open_interest_fp, yes_bid_size_fp, yes_ask_size_fp, last_trade_size_fp and ts_ms, flushed about once per second per changed market. Kalshi documentation official source verified
S16 WebSocket connections use the same Kalshi API-key authentication, subscribe via {"id":1,"cmd":"subscribe","params":{"channels":[…],"market_tickers":[…]}}, and must resubscribe after a reconnect. Kalshi documentation official source verified
S17 GET /portfolio/balance returns balance (cents), balance_dollars and portfolio_value (cents), updated_ts, and a per-exchange-index balance_breakdown. Kalshi documentation official source verified
S18 GET /portfolio/positions returns market_positions with ticker, position_fp (positive = YES, negative = NO), market_exposure_dollars, realized_pnl_dollars, fees_paid_dollars and total_traded_dollars. Kalshi documentation official source verified
S19 Fees are executed at six-decimal dollar granularity with round-up behaviour and a rounding-fee accumulator; direct members settle balances to $0.0001, non-direct members to $0.01. Kalshi documentation official source verified
S20 The demo environment is https://demo.kalshi.co, uses mock funds, has credentials separate from production, and Kalshi warns that demo prices and behaviour may not reflect real markets. Kalshi documentation official source verified
S21 A demo account is created by the account holder at demo.kalshi.co/sign-up, is not preloaded with funds, and accepts test payment methods; demo credentials are separate from production. Kalshi Help Center official source verified
S22 REST market data is cached briefly, so prices, sizes and status can lag the exchange by several seconds; WebSockets are the documented mechanism for current prices. Kalshi documentation — Data Freshness section official source verified
S23 OpenAPI spec lists four supported servers: external-api.kalshi.com, api.elections.kalshi.com, external-api.demo.kalshi.co and demo-api.kalshi.co, all under /trade-api/v2. Kalshi documentation — OpenAPI spec official source verified
S24 GET /exchange/status returns exchange_active, trading_active and per-exchange-index statuses. Live demo read on 2026-11-22 returned exchange_active=true, trading_active=true across four indexes. Kalshi demo API (live read) official source verified
S25 Live production read on 2026-11-22: GET /markets?series_ticker=KXAAAGASM&status=open returned strikes 3.45 / 3.55 / 3.65 with prices, volume_fp and open_interest_fp; GET /series?tags=Golf returned KXPGAEAGLE, KXLIVR1LEAD and KXRYDERCUPCAPTAIN among others. Kalshi production API (live read) official source verified

6 · Deliberately left blank

  • Kalshi demo balance, positions and P&L — no demo credentials exist in this environment; the fields are absent rather than filled (see F2).
  • Official trading-fee rate — the fee-schedule PDF could not be retrieved; the model is labelled unverified everywhere it affects a number (see F1).
  • Default API key type — no official statement found, so no claim is made (see F11).
  • Browser CORS behaviour — not testable from the build environment; the UI tests it live and reports the result instead of assuming it (see F5).
  • News attribution for individual jumps — no causal claim is made about why a contract moved; the dashboard links the market's own settlement sources and the Kalshi market page so a trader can check (proposal #5 on the strategies page).

7 · Reproducing this build

git clone https://github.com/kanlerxz87-cyber/Tradebot1.git
cd Tradebot1
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q                  # 48 unit tests
.venv/bin/python -m kalshi_trader.cli collect  # one live cycle → docs/data/*.json
.venv/bin/python tools/build_site.py           # regenerate static tables
.venv/bin/python tools/check_links.py          # verify every internal link
.venv/bin/python -m kalshi_trader.cli serve    # live site on :8000
