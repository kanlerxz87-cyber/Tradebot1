Executive summary

A live research desk for five Kalshi topics — gas prices, elections, culture, crypto, golf — that detects ≥ $0.10 price swings, ranks them, tracks events to settlement, and trades the same signals autonomously in a simulated book. Built from an empty repository, verified against official Kalshi documentation, and published as a static site refreshed by a scheduled job.

The one-paragraph version

Kalshi's public market-data API needs no key, which makes a fully autonomous dashboard possible: a scheduled job scans every open event, filters to the five requested topics using Kalshi's own category and tag taxonomy, records prices, detects moves of at least ten cents, and writes a compact JSON snapshot that a static site renders. A second, independent loop trades those signals in a simulated ledger and settles positions on the exchange's reported outcome, so every strategy has a record instead of an opinion. Execution against a real demo account is implemented and dormant: it activates the moment demo credentials exist, and until then the site says so instead of inventing a balance.

What is live

Delivered

  • Dashboard — five-topic market table, highest-dollar event leaderboard, two alert chats, price chart with 30s→all windows, orderbook depth, resolution tracker, portfolio strip.
  • Five topic pages with server-rendered tables and a source link on every row.
  • Four strategies, a transparent ROI score, and the exact thresholds behind the second chat.
  • Portfolio analytics — equity curve, win rate, profit factor, expectancy, drawdown, P&L by strategy, topic, price band and exit reason.
  • Verification log with 25 sourced claims plus live API reads.
  • Flagged for review — 14 items, each with handling and a clear condition.

Autonomy

  • A GitHub Actions cron runs the collector every 30 minutes, commits the new snapshot and advances the paper book.
  • No user action is required for the site to stay current; a stale snapshot is visibly labelled after 30 minutes.
  • Every failure (network, rate limit, unknown field) is recorded in the snapshot and printed on the page rather than silently swallowed.
  • The local server adds seconds-level collection, a same-origin proxy and WebSocket push when you want a faster loop.

Decisions worth knowing

Data from production, execution in paper

Production public data is keyless, real and carries real volume. The demo environment is a sandbox that Kalshi itself warns may not reflect real markets. Reading production and executing in a simulated book keeps the two roles honest; switching to demo data is one environment variable. Flagged as F6.

Static site plus a real collector

GitHub Pages cannot poll an exchange, so the alternative is either a fake “live” label or a scheduled collector that commits what it saw. The second is real: the page always shows the snapshot's timestamp and turns amber after 30 minutes. Flagged as F10.

Nothing is estimated into a blank

No demo balance, no fee number presented as official, no causal news claim. Missing values render as “—” and the reason appears on the Flagged page. This is the single rule the whole build is organised around.

The model is deliberately boring

Six weighted components, published weights, a version string, and a disclaimer printed next to every result. It exists to reduce alert noise, not to predict. Its accuracy will be whatever the ledger measures.
