Executive summary

A source-linked research and paper-trading desk for five Kalshi topics — gas prices, elections, culture, crypto, and golf. It records observed ≥ $0.10 swings, shows time/price charts and order-book depth, tracks markets through final settlement, and keeps simulated strategy results separate from exchange account activity. GitHub Pages serves scheduled snapshots; it is not an always-on exchange connection.

What this build does

Kalshi documents public market-data reads separately from authenticated account requests. The scheduled collector records official observations for the five requested topics and writes a source-linked snapshot for the static site. One feed shows observed moves of at least ten cents; a second shows only candidates that pass a documented heuristic. Paper strategies use a local ledger and exchange-reported outcomes, not the Demo-account balance. The optional protected Demo order route is a separate server feature; it is disabled unless a trusted host has credentials and an explicit execution enable flag. No authenticated Demo order, fill, balance, or WebSocket session was verified for this publication.

What is delivered

Delivered

  • Dashboard — five-topic market table, a labelled estimated 24-hour-dollar ranking (contract volume × price), two observed-swing feeds, time/price chart, order-book depth and resolution tracker. It is not a complete exchange-wide dollar-turnover ranking.
  • Five topic pages with server-rendered tables and official source links on market rows.
  • Four paper strategies and a documented heuristic screen; the score is not a validated ROI forecast.
  • Paper portfolio analytics — equity, settled trades and breakdowns by strategy/topic. These are simulated results, not Demo-account performance.
  • Verification log with dated official-source claims and the corresponding capture provenance.
  • Flagged for review — open limitations, source links and intentionally blank unverified account values.

Autonomy

  • GitHub Actions schedules public market-data collection and publishes timestamped snapshots; this static site is not a continuous exchange stream.
  • No account input is needed for public observations or paper simulation. Snapshot age and collection errors are shown rather than replaced with invented values.
  • Failures such as network errors, rate limits or unknown fields are recorded in the snapshot and disclosed on the page.
  • A separate Demo service implementation provides lower-latency collection and protected account routes; it is not part of the static Pages deployment, and its exchange connection and account execution are not verified here.

Decisions worth knowing

Demo data, execution in paper

The scheduled collector and local default now use Kalshi's demo REST API; the browser and static builders reject snapshots unless both the environment label and REST root match an official demo endpoint. The committed snapshot still identifies production data and is withheld until a successful demo-only cycle replaces it. Flagged as F6.

Static site plus a real collector

GitHub Pages cannot poll an exchange, so the alternative is either a fake “live” label or a scheduled collector that commits what it saw. The second is real: the page always shows the snapshot's timestamp and turns amber after 30 minutes. Flagged as F10.

Nothing is estimated into a blank

No demo balance, no fee number presented as official, no causal news claim. Missing values render as “—” and the reason appears on the Flagged page. This is the single rule the whole build is organised around.

The model is deliberately boring

Six weighted components, published weights, a version string, and a disclaimer printed next to every result. It exists to reduce alert noise, not to predict. Its accuracy will be whatever the ledger measures.

Next three moves

  1. Align the root research desk with the requested Demo source, or clearly label production read-only data in its primary status badge; refresh only from an official, timestamped Demo response.
  2. Keep account keys on a separately hosted trusted service. GitHub Pages cannot hold signing credentials; no private key or account access was available to this review, so no Demo balance or exchange fill is claimed.
  3. Before describing the selected alert feed as high ROI, compare it out of sample with fee-aware simulated fills; keep possible-news links explicitly separate from causal evidence.
