Strategies and the ROI model

Four rule sets, one hand-built score, and a strict separation between what is measured and what is assumed. Everything here is inspectable: the weights, the thresholds, the sizing rule and the exit rule are the same numbers the code uses.

1 · The four strategies

Two react to swing alerts, two trade the standing book. Each one exists to be falsified, not to look clever.

Momentum continuation alert-driven

A $0.10+ move on a liquid, tight book tends to continue briefly. Buy the side that just moved.

Entry
alert direction, model score ≥ 0.45, spread ≤ $0.06, 24h volume ≥ 250
Exit
+$0.10 target, −$0.10 stop, or 24h

Swing fade alert-driven

Large single-cycle moves in thin books often partially retrace. Take the other side of the alert.

Entry
opposite of alert direction, score ≥ 0.30, spread ≤ $0.08, 24h volume ≥ 100
Exit
+$0.08 target, −$0.12 stop, or 6h

Late favourite standing rule

Contracts priced 0.85–0.96 with real volume are usually near-certain; the residual premium is small and the hit rate is historically high. Hold to settlement.

Entry
price 0.85–0.96, 24h volume ≥ 500, closes within 7 days
Exit
−$0.15 stop or settlement

Cheap upside standing rule

Low-priced contracts with heavy volume are cheap convexity. Same fixed-fraction sizing, so a run of losses cannot wipe the book.

Entry
price 0.03–0.10, 24h volume ≥ 1,000, closes within 30 days
Exit
settlement
Benchmark: holding cash. A strategy that cannot beat cash after fees is not adding value, and the portfolio page shows the cash line implicitly through the bankroll start.

2 · The high-ROI model

Used for exactly one thing: deciding which alerts reach the second chat. It is a heuristic score in [0, 1], not a forecast, and it is versioned heuristic-v1.

Weights

ComponentWeightInput
Momentum0.40move over 10 minutes, else 1 hour
Liquidity0.20log-scaled 24h contract volume
Open interest0.15log-scaled open contracts
Price band0.101.0 at $0.50, falling towards the tails
Time to close0.151.0 for 15 min–72 h, 0.6 to 7 days, 0.3 beyond
Spread penalty−0.20spread ÷ $0.10, capped at 1

Filter and estimate

An alert reaches the high-ROI chat only when all four hold:

  • score ≥ 0.45
  • estimated ROI ≥ 6%
  • spread ≤ $0.06
  • 24h volume ≥ 100 contracts

The estimated ROI is the score scaled by the observed move and divided by the entry price:

roi% ≈ score × min(0.30, |move| + 0.04) ÷ price × 100

It answers “if a move of this size repeated, what share of the premium would that be worth?” — it is not a probability of profit.

Stated plainly: the weights are starting assumptions. The dashboard publishes them so they can be replaced by measured results (see F12). Treat a green chip as “worth a look”, not as a signal to trade.

3 · Risk and sizing

Position sizing

risk = equity × 2%
contracts = floor(risk ÷ ask price)
contracts = min(contracts, visible top-of-book size)

Long-only and cash-secured, so the worst case per position is premium + fees. Maximum 12 open positions, one per market per strategy.

Why whole contracts

Kalshi supports fractional contracts down to 0.01, but rounding down guarantees the simulated book never assumes more size than a real order could have taken at the displayed price. Conservative on purpose.

5 · Running the live server

Commands

python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m kalshi_trader.cli collect     # one cycle
.venv/bin/python -m kalshi_trader.cli serve       # site + API + WebSocket

The server serves the same docs/ site, collects on an interval and pushes each cycle to every open tab over /ws.

Why a server at all

GitHub Pages is static: it can serve the data but cannot poll Kalshi. The server adds collection, a same-origin proxy (which sidesteps browser CORS entirely) and WebSocket push. The site degrades gracefully to the committed snapshot when neither is available.
