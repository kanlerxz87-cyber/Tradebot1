These items do not block the release — the site states its uncertainty rather than hiding it. Two are material for interpreting results: the fee model (F1) and the missing demo account (F2). The rest are documentation, mapping and hosting realities.

F1 warn Trading-fee formula is unverified
The paper book charges a fee of ceil_to_cent(0.07 × contracts × price × (1 − price)). Kalshi's fee schedule PDF (linked from the fee_type field of GET /series) could not be retrieved during this session, so the formula is only supported by third-party write-ups, not by an official Kalshi document.
Handling: Every ledger entry is labelled fee_model=quadratic_unverified; the portfolio page states the caveat next to P&L; KALSHI_FEE_MODEL=none disables fees entirely so results can be compared with and without them.
Would be cleared by: Retrieve the current fee schedule PDF and set VERIFIED=True with the published rate in kalshi_trader/fees.py.

F2 warn Demo account is not connected — no live demo P&L
A Kalshi demo account and its API key can only be created by the account holder (demo.kalshi.co sign-up plus test-funding). This session cannot create one, so no demo balance, positions or fills exist to report. Nothing is estimated in their place.
Handling: Simulated trading runs autonomously in an internal ledger. The demo adapter (kalshi_trader/kalshi_demo.py) activates automatically when KALSHI_API_KEY_ID and KALSHI_PRIVATE_KEY are present; the dashboard shows an explicit 'not connected' block until then.
Would be cleared by: Add demo API credentials as repository secrets; the next scheduled cycle reads the demo balance and mirrors new entries as demo orders.
help.kalshi.com/en/articles/13823775-creating-and-us · docs.kalshi.com/api-reference/portfolio/get-balance
F3 info 'Culture' is a mapping, not an official Kalshi category
The official category list contains Entertainment, Social, Mentions, Politics and others — there is no 'Culture' category. The brief's culture topic is mapped to the official Entertainment category plus Social when a series carries it, which is a documented editorial decision.
Handling: The mapping is declared in kalshi_trader/topics.py, printed on the Culture page, and every row keeps its raw category so the mapping can be audited or changed.
Would be cleared by: If Kalshi publishes a Culture category, add it to the mapping and drop Entertainment/Social.
docs.kalshi.com/getting_started/terms · docs.kalshi.com/api-reference/search/get-tags-for-se
F4 info Golf and gas-price topics need two matching paths
Golf is a tag under Sports, and the US gas-price series KXAAAGASM sits under Economics/Commodities. Series that omit the tag or the expected title would otherwise be missed, so a keyword fallback (golf/PGA/LPGA/Ryder Cup/LIV; gas price/gasoline/average gas) is used after the taxonomy match.
Handling: Taxonomy match always wins; the fallback is only applied when the official fields do not classify the series. Both paths are unit-tested and visible in the code.
Would be cleared by: Drop the keyword fallback once Kalshi guarantees complete tagging for these series.
docs.kalshi.com/getting_started/terms · docs.kalshi.com/api-reference/search/get-tags-for-se
F5 info Browser CORS access to the Kalshi API is untested
GitHub Pages is static, so live data must come either from a committed snapshot or from the visitor's browser calling Kalshi directly. Whether Kalshi sends permissive CORS headers could not be determined from the documentation.
Handling: The published snapshot is the default data path (it cannot be blocked by CORS). The UI offers an explicit 'test live access' action and reports the result honestly; the included local server provides a same-origin proxy and WebSocket push.
Would be cleared by: Confirm CORS behaviour in a browser, or deploy the included server behind the site.
docs.kalshi.com/getting_started/quick_start_market_d · docs.kalshi.com/getting_started/api_environments
F6 warn Market data source is production while execution is paper
Market data uses the production public endpoints because they are keyless, carry real volume and reflect real prices. Execution is the internal paper ledger. Kalshi warns that demo prices may not reflect real markets, so demo fills and production marks would not be strictly comparable.
Handling: The dashboard always names its data environment and execution mode. Switching to demo data is one environment variable (KALSHI_DATA_ENV=demo).
Would be cleared by: Run the dashboard against the demo environment once demo credentials exist, and compare the two books side by side.
docs.kalshi.com/getting_started/demo_env · docs.kalshi.com/getting_started/api_environments
F7 info Alert timing is cycle-resolution, not tick-resolution
Kalshi documents that REST market reads are cached briefly and can lag by seconds. The scheduled collector runs every 15 minutes, so a swing is detected between consecutive cycles; the live server and direct mode raise the resolution to seconds.
Handling: Every alert records its timestamp, the compared-from price and the basis (midpoint or last), so the detection window is auditable rather than implied.
Would be cleared by: Subscribe to the orderbook_delta WebSocket channel for tick-level detection once credentials exist.
docs.kalshi.com/getting_started/quick_start_market_d · docs.kalshi.com/getting_started/rate_limits
F8 info Dollar-volume and dollar-open-interest figures are derived
The market object reports contract counts (volume_24h_fp, open_interest_fp), not dollars. 'Est. 24h $' is computed as volume_24h × price and 'OI $' as open interest × price.
Handling: Derived fields carry an _est suffix, are listed in DERIVED_FIELDS in kalshi_trader/marketdata.py, and the dashboard labels them 'estimated, derived' wherever they appear.
Would be cleared by: Use the dollar_volume field from the ticker WebSocket channel, which Kalshi reports directly.
docs.kalshi.com/api-reference/market/get-markets
F9 info Orderbook asks are implied, not reported
Kalshi returns bids only. YES asks are computed as $1.00 − the best NO bid, and NO asks as $1.00 − the best YES bid.
Handling: The depth panel labels the ask column 'implied from NO bids' and the methodology page shows the arithmetic.
Would be cleared by: None needed; this is how a binary book works.
docs.kalshi.com/getting_started/orderbook_responses
F10 info GitHub Pages cannot schedule work
The published site is static. Freshness depends on the GitHub Actions cron job that collects data and commits it under docs/data/.
Handling: The page shows the snapshot age and turns the freshness chip amber after 30 minutes; the workflow and its last run are linked from the verification page.
Would be cleared by: Run the included server for true live streaming, or accept the 15-minute cadence.
docs.github.com/en/pages
F11 info Ed25519 default-key claim is not used
Some third-party guides state that Ed25519 became the default API key type on 2026-10-01. The official pages read during this session describe support for both RSA (RSA-PSS/SHA-256) and Ed25519 but do not state a default date.
Handling: The signer detects the key type at runtime and supports both; no claim about a default is made anywhere on the site.
Would be cleared by: Cite the official announcement if one is published.
docs.kalshi.com/api-reference/portfolio/get-position · docs.kalshi.com/getting_started/api_environments
F12 warn The ROI model is a transparent heuristic, not a validated alpha
The high-ROI chat is filtered by a hand-built score (momentum, liquidity, open interest, price band, time to close, spread penalty). It has no backtested accuracy claim; its hit rate is whatever the autonomous book records from now on.
Handling: Every pick exposes its components, inputs and version; the strategies page states plainly that the weights are starting assumptions to be replaced by measured results.
Would be cleared by: Re-fit the weights on accumulated paper results and publish the out-of-sample comparison.
docs.kalshi.com/getting_started/market_lifecycle
F13 info Per-topic caps bound the ranking universe
Each cycle keeps at most 40 series and 60 markets per topic after scanning all open events, ranking by estimated notional. 'Highest dollar amount live events' therefore means the highest inside the tracked subset, not a guarantee of the global top of the exchange.
Handling: The caps are configuration (MAX_SERIES_PER_TOPIC, KALSHI_MAX_MARKETS_PER_TOPIC) and the counts actually scanned are printed on each topic page.
Would be cleared by: Raise the caps (at a request-cost trade-off) or paginate more aggressively.
