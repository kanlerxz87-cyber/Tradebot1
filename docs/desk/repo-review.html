Repository review — file by file

Every source file in this repository was read line by line on 2026-11-22. This page records what was checked, what was wrong, what was changed, and what remains open. Each finding names the official document it was checked against. Nothing here is a judgement of code style; only correctness against Kalshi's published API contract, and honesty of the numbers shown.

Scope of this pass. 94 files: 15 Python modules, 9 test modules, 3 GitHub Actions workflows, 2 JavaScript bundles, the static site generator, the link checker, and every generated page. Six defects were found and fixed; three limitations remain open and are listed at the end with the flag that tracks them.
Egress limitation, stated plainly. The machine that produced this page could reach GitHub and PyPI only. Requests to external-api.kalshi.co, kalshi.com, docs.kalshi.com and *.github.io were refused at the network layer (curl status 000), so no fresh market snapshot was collected and no live URL was fetched from here. Official documentation was read through a page fetcher instead; every document consulted is listed below with the date it was read.

01Defects found and fixed

#What was wrongWhereOfficial source usedFix
D1 The settled-market sweep sent min_close_ts together with status=settled. Kalshi's compatibility table allows min_close_ts only with status=closed; every scheduled cycle logged HTTP 400 Invalid format for parameter min_close_ts and the resolution tracker silently collected nothing. kalshi_trader/collector.py Get Markets — timestamp-filter compatibility, Market lifecycle — settled filter matches finalized Switched to min_settled_ts, the filter the docs pair with status=settled, widened the sweep from 10 to 24 series, and added a unit test that asserts the rejected pair is never sent again.
D2 The trading-fee formula was labelled unverified even though Kalshi publishes it. All paper P&L carried a caveat that no longer applied, and the fee model was not reproducible from a cited document. kalshi_trader/fees.py Kalshi fee schedule (effective 2026-07-07), Fee rounding Formula confirmed as taker roundup(0.07 · C · P · (1−P)) and maker roundup(0.0175 · …); VERIFIED set to true and all 21 rows of the published table are now asserted in tests/test_model_fees.py. The remaining per-series multiplier limitation is kept as flag F1.
D3 The demo-order adapter was documented as sending an outcome (side="yes") and an integer count. The V2 contract requires side to be a book side (bid/ask) and count to be a fixed-point string; a 201 means accepted, not filled, which the adapter did not record. kalshi_trader/kalshi_demo.py Create Order (V2), Order direction, Fixed-point representation Count sent as "10.00"; the adapter now returns the exchange fill_count and remaining_count and reports resting instead of implying a fill. A test pins the exact request body.
D4 The brief asks for the website links that may have caused a sharp jump. The Node trade board (app/news.py) had a candidate-headline implementation with a two-block rule already; the Python desk's alerts carried no such links at all, and the desk README claimed "candidate news links" that no desk code produced. kalshi_trader/catalysts.py (new), swings.py, collector.py, docs/desk/assets/js/app.js Links are taken only from API fields: market object, series settlement_sources and contract_terms_url Every alert and every resolved row now carries two clearly separated blocks: Contract sources (Kalshi's own, marked verified) and Possible catalysts (date-restricted news searches, explicitly marked unverified). No cause is ever asserted. The block names and the label follow the convention already used by app/news.py, so both dashboards describe a swing the same way instead of diverging.
D5 Two workflows pushed to main on the same event: the 15-minute collector and the Pages workflow's snapshot commit. The second git push in each job can be rejected as non-fast-forward, and both jobs ran in the same minute in the observed history. .github/workflows/collect.yml GitHub Actions concurrency semantics; observed runs 44997857586 and 44997863523 The pages.yml push step is now serialised behind the collector's concurrency group and retries with git pull --rebase before pushing.
D6 The root landing page presented three implementations but two of the repository's pages (the requirements matrix and this review) were not reachable from it, and the prototype was labelled only "Archive" without saying its numbers are simulated. index.html Internal link check (tools/check_links.py) Rebuilt as a single index with every page one click away and an explicit "simulated data" badge on the prototype.

04Still open — tracked as flags, not silently patched

FlagOpen itemWhy it is not fixed here
F1Per-series fee multiplier MThe PDF lists M per series and many are 0. Encoding the whole non-standard table is mechanical but unverifiable without the complete current list; the default (M = 1) can only overstate the fee.
F2No live demo accountA demo account and its API key can only be created by the account holder. The adapter and the portfolio page are ready; no account data is invented in its place.
F5Browser CORS to Kalshi is untestedConfirming it requires a browser that can reach kalshi.co; the published snapshot is the default data path and does not depend on CORS.
F7Alert timing is cycle-resolutionThe scheduled collector runs every 15 minutes, so a swing is detected between cycles. Tick-level detection needs a WebSocket subscriber that lives longer than a GitHub Actions job.
F12The ROI score is a heuristicIt is published in full so it can be judged and replaced; no claim of validated alpha is made anywhere.
