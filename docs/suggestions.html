Making the site more live and interactive

GitHub Pages is static hosting: it cannot hold a WebSocket open or run a server-side process. This dashboard works around that with a scheduled GitHub Actions collector (every ~10 minutes, GitHub's documented minimum cron interval is 5 minutes and public-repo schedules can run later under load). Below is a concrete, honest list of what would make it feel more "live", roughly ordered by effort.

Low effort

Sparkline per market row
Tiny inline canvas chart next to each ticker in the market tables, using data already collected.
Browser notifications
Notification API permission prompt on the alerts page, firing a desktop toast on new ≥$0.10 moves while the tab is open.
User-configurable threshold
Let the viewer raise/lower the $0.10 alert threshold client-side (filtering the same feed), saved in localStorage.
Dark/light mode toggle
The dashboard ships dark-only today; a toggle is a CSS variable swap.
Sound cue on alert
Optional short chime when a new high-ROI alert streams in, muted by default.
"Replay" scrubber
A slider over history/*.json to scrub back through the day's price history, not just view the live edge.

Medium effort

Tighter collector cadence
Run on a self-hosted runner or a small always-on worker (e.g. a free-tier cloud function) instead of GitHub Actions cron, to legally go below the 5-minute floor.
News-link enrichment
On any ≥$0.10 move, auto-query a news search for the market's topic keywords around that timestamp and attach the top 1–2 headlines/links as the probable cause — shown directly in the alert feed.
Per-market order-book depth chart
Use /markets/{ticker}/orderbook (confirmed endpoint) to show a simple bar chart of contracts available at each nearby price level, not just the top-of-book price.
Saved watchlists
Let a visitor star specific tickers across topics into one personal cross-topic feed, stored client-side.

Higher effort (needs a small always-on backend)

True WebSocket streaming
A tiny relay service (outside GitHub Pages) holds the authenticated Kalshi WebSocket connection open and re-broadcasts ticker/trade messages to connected browsers over its own WebSocket or Server-Sent Events — this is the only way to get sub-second updates; static Pages fundamentally cannot do this alone.
Real demo-account execution
Add the user's own Kalshi demo API key as a GitHub Actions secret (see scripts/README.md) and call the authenticated /portfolio/events/orders endpoints instead of only paper-trading.
Polymarket comparison view
Where an equivalent market exists on Polymarket, show both prices side by side — clearly labeled as a separate, non-Kalshi data source, never blended into the Kalshi tables.

What this build already does to feel live within those constraints

  • Two scrolling "chat" feeds (All Events / High-ROI) that re-poll every 20 seconds.
  • Per-topic price charts with a seconds / minutes / hours look-back selector.
  • An equity curve for the simulated portfolio, updated every collector run.
  • Explicit "last updated" / "no data yet" badges everywhere, so nothing ever looks live when it isn't.
