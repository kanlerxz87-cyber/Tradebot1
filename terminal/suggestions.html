P0 — unblocks genuinely live behaviour

RefSuggestionWhy it mattersEffortOfficial source
P0-1Add a small WebSocket proxy (Cloudflare Worker or ~40-line Node service) that signs the handshake, then forwards frames to the browser.Kalshi's WS upgrade requires the signed KALSHI-ACCESS-* headers; browsers cannot set custom headers on new WebSocket(). With a proxy the dashboard can switch from 4 s polls to push updates — order-book deltas and ticker messages arrive in milliseconds, and alerts stop depending on a polling window.~1 hour, one deploy targetQuick Start: WebSockets ↗ · API Keys ↗
P0-2Snapshot service for history. A GitHub Action (or cron Worker) writes a public JSON snapshot every 1–5 min into the repo; the site reads history from it.REST candles only exist at 1 m / 1 h / 1 d granularity; sub-minute windows shown live today are built from in-browser polling and vanish on reload. A snapshot endpoint gives a durable, shareable history without any credentials (public read endpoints need no auth).~2 hours, existing Actions runnerCandlesticks API ↗ · Quick Start: Market Data ↗

P1 — high value, small effort

RefSuggestionWhy it mattersEffortOfficial source
P1-1Alert fan-out to email/Slack/Discord webhooks, triggered by a scheduled collector.A trader is not always watching a browser tab. Fan-out requires a server-side trigger, which the demo REST API supports from a runner with no special permission for reads.~2 hoursAPI Environments ↗
P1-2Contract-side breakouts: detect moves on YES and NO independently and show both in the same chat with the side label.A NO-side jump of $0.10 is a YES price drop; traders watch the side they hold. One extra comparison per contract.~30 minOrderbook responses ↗
P1-3Liquidity sparkline beside each event row (top-of-book size + spread).Price without depth is misleading: a $0.10 move on 5 contracts is noise, the same move on 5,000 is not. Depth is already in the order book response; it just needs a small chart.~1 hourOrderbook responses ↗
P1-4Per-topic playbooks (see table below) surfaced as one-line "what usually moves this" hints next to each topic card.Converts the dashboard from a price wall into a decision surface. Playbooks are labelled as editorial notes, never as verified facts.~1 hour contentInternal notes; gas series taxonomy: Market terms ↗
P1-5Saved views (URL hash encodes topic, window, chat filter) so a trader can bookmark a layout.Live dashboards earn their keep when the exact layout survives a reload; today only the topic is deep-linkable.~45 minInternal (this site)

P2 — analytics depth

RefSuggestionWhy it mattersEffortOfficial source
P2-1News-correlation pipeline. When a ≥ $0.10 swing fires, search a news API over the previous 15 minutes for the event's named subject (EIA release, FEC filing, tournament leaderboard, coin price feed), store the top matches beside the alert with timestamps.Today the alert shows "possible drivers to check" search links, not a correlation. A stored join (alert time ↔ article time ↔ topic keywords) turns that into evidence a human can audit — still shown as candidate, never as cause.~1 day + a news API keyMarket lifecycle ↗ (settlement sources)
P2-2Calibration scoreboard: bucket the simulated book's trades by model score and plot realised hit rate per bucket.The score is a heuristic; the only honest measure of it is out-of-sample. Buckets make overfit visible.~3 hoursInternal — model rubric ↗
P2-3Settlement-aware auto-close: poll settled markets and move paper positions to cash at $1/$0 automatically.Resolution is already tracked; wiring the payout into the book closes the loop without manual clicks.~2 hoursMarket settlement ↗
P2-4Cross-topic correlation card: show a matrix of how today's topics moved together (crypto vs elections etc.).Useful only after several days of snapshot history exist (depends on P0-2).~4 hoursDepends on P0-2
