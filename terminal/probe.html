Live connection probe

Every data call this site makes is sent from your browser to the Kalshi demo environment. That is what makes it live — and it means a blocking firewall, an offline laptop or a CORS policy looks exactly like “no data”. This page runs each call once and prints the real HTTP status, timing and a fragment of the response, so a failure can be reported instead of guessed at.

What this proves. A green row means this browser, right now received a successful response from that endpoint. It is evidence for you, not a claim about anyone else's connection. Nothing here is cached, retried silently, or filled in when it fails.

How to read a failure

HTTP 0 / “Failed to fetch”. The request never completed. Causes: no internet, a corporate proxy or firewall, an extension blocking the host, or the demo host being down. The dashboard cannot fix this and will say “DISCONNECTED” rather than show stale numbers as if they were live.

A CORS error in the console. The browser refused to hand the response to this page. Public market data from the demo hosts has been measured as CORS-allowed (see the verification register and the repository's probe/results.json); if you see one, report the exact endpoint.

HTTP 401 on a /portfolio/… route. Expected: those routes need a signed request with your own demo key. Signed requests from a browser are also blocked at the preflight stage by the exchange's allowed-header list, which is why the Portfolio page explains the limitation before you try.

HTTP 429. Rate limited. The dashboard backs off automatically and says so.
